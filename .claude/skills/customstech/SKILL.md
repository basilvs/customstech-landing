# CustomsTech landing

Репозиторий `customstech-landing` — статический продуктовый лендинг (чистый HTML/CSS/JS, без сборки и зависимостей), публикуется через GitHub Pages. Показывает живую ленту новостей таможенного законодательства — реальный выход конвейера автопостинга из `customs-ops-toolkit`.

Живo: https://basilvs.github.io/customstech-landing/

## Структура

```
index.html          — единственная точка входа, вся разметка и CSS/JS inline
news-data.js        — массив NEWS_FEED: записи ленты (реальный выход конвейера)
assets/news/        — изображения и видео к новостям (PNG/MP4)
assets/screenshots/ — скриншоты для README (desktop/mobile/фильтр/полная страница)
docs/               — 30-дневный план, отчёты статуса, lighthouse-отчёты
README.md           — описание продукта, запуск, структура, дорожная карта
.gitignore          — Thumbs.db, .DS_Store
```

### Секции `index.html`

| id секции | Назначение |
|---|---|
| `hero` | Первый экран, заголовок |
| `news` | Лента новостей: `#newsFilters` (кнопки тем) + `#newsGrid` (карточки) |
| `pipeline` | «Как это работает» — 6 агентов конвейера |
| `roadmap` | Дорожная карта (таблица этапов) |
| `benefits` | «Эффект уже сейчас» |
| `demo` | Форма заявки — **макет без бэкенда**, отправка эмулируется `alert()` |

### Запись в `news-data.js`

```js
{
  date: "YYYY-MM-DD",
  topic: "Декларирование",   // Декларирование | Пошлины | Контроль | Экспорт | НПА
  title: "...",
  summary: "...",
  source: "alta.ru",          // домен первоисточника
  url: "https://...",         // HTTPS, открывается с rel="noopener"
  image: "assets/news/<slug>.png"  // или .mp4; loading="lazy" ставит рендер
}
```

Записи идут от новых к старым (по `date` desc). Фильтры тем собираются автоматически из `new Set(NEWS_FEED.map(n => n.topic))`.

## Локальный запуск

Зависимостей нет. Два варианта.

**Просто открыть файл** — двойной клик `index.html`. Работает без сервера.

**Через локальный сервер** (нужно для теста на телефоне / Lighthouse / Playwright):

```bash
py -m http.server 8000
# затем http://127.0.0.1:8000/
```

или

```bash
npx serve .
```

Останавливать сервер перед коммитом не обязательно, но проверь, что порт свободен: `netstat -ano | findstr :8000`.

## Внесение изменений

### Добавить новость в ленту

1. Положить медиа в `assets/news/` с именем `YYYY-MM-DD-<slug>.png` (или `.mp4`).
2. Добавить объект в начало массива `NEWS_FEED` в `news-data.js` по схеме выше.
3. Проверить, что `topic` совпадает с одним из существующих (иначе появится новая кнопка фильтра — это нормально, если тема новая).
4. Проверить, что `image` указывает на существующий файл.

### Поправить секцию `index.html`

CSS и JS встроены в `<style>` и `<script>` того же файла. Секции — `<section class="section" id="...">`. Менять адаптив — в медиа-запросах внизу `<style>` (breakpoint ~768px).

### Форма демо — макет

Не превращать форму в «рабочую» без явного указания пользователя. Отправка эмулируется `alert()`, под формой есть примечание «макет интерфейса без бэкенда». Это сделано намеренно — не убирать оговорку.

## Обновление README

README описывает продукт, сценарий, запуск, структуру, дорожную карту. Держи в синхронизации с реальностью.

Когда что менять:

| Изменение в коде | Что обновить в README |
|---|---|
| Новая секция в `index.html` | Раздел «Структура проекта» / «Демонстрация» |
| Новый скриншот в `assets/screenshots/` | Блок `## Демонстрация` — вставить `![...](assets/screenshots/...)` |
| Сдвиг этапа дорожной карты | Таблица `## Дорожная карта` (✅/🔜/🔮) |
| Новая категория метрик/проверок | `## Технические детали` |
| Отчёт статуса в `docs/` | Ссылка в «Дорожная карта» / «Технические детали» |

Правило: после правок в коде проверить, не устарел ли соответствующий раздел README. Скриншоты делаются с запущенного локального сервера.

## Проверка ошибок

### 1. Консоль браузера (минимум)

Открыть `http://127.0.0.1:8000/` в Chromium → DevTools → Console. Ожидается: пусто. Любые 404 на `assets/news/*`, ошибки `NEWS_FEED is not defined` — блокеры.

### 2. Playwright (если доступен)

Прогнать страницу через Playwright MCP, собрать ошибки консоли и падения сети. Критично: отсутствие 4xx/5xx и JS-исключений.

### 3. Lighthouse

Методика — в `docs/lighthouse-report-2026-08-11.md`. Кратко:

```bash
py -m http.server 8000
```

DevTools → Lighthouse → Mode: Navigation → Device: Mobile/Desktop → Categories: all → Analyze.

Пороговые метрики:

| Категория | Минимум |
|---|---|
| Performance | ≥ 90 |
| Accessibility | ≥ 95 |
| Best Practices | ≥ 90 |
| SEO | ≥ 90 |

Если метрика ниже — смотреть рекомендации в `docs/lighthouse-report-2026-08-11.md` (WebP/AVIF, `aria-expanded`, `canonical`, sitemap).

### 4. Целостность связей

Перед публикацией проверить, что:
- все `image` в `news-data.js` указывают на существующие файлы `assets/news/`;
- все `url` новостей — HTTPS и рабочие;
- внешние ссылки открываются с `rel="noopener"`;
- `<html lang="ru">`, мета-теги, Open Graph, Schema.org (JSON-LD) на месте.

## Подготовка к публикации

Публикация — через GitHub Pages: при пуше в `master` сайт обновляется на `https://basilvs.github.io/customstech-landing/`.

### Чек-лист перед коммитом

1. Локальный сервер поднят, страница открывается, консоль чиста.
2. Lighthouse ≥ порогов (см. выше) или зафиксированная причина отклонения.
3. README синхронизирован с изменениями.
4. Скриншоты в `assets/screenshots/` актуальны (если менялся UI).
5. `docs/` — отчёт статуса с датой, если этап сдвинулся (файл вида `YYYY-MM-DD — статус плана развития — отчет.md`).
6. Нет временных/системных файлов (`.Thumbs.db` и т.п. — в `.gitignore`).

### Коммит

Сообщения — короткие, в настоящем времени, по-английски (как существующие: «Add August 2026 customs news: ...», «Add Schema.org, Lighthouse report, ...»).

```bash
git add -A
git commit -m "<что сделано>"
git push origin master
```

После пуша: проверить `https://basilvs.github.io/customstech-landing/` (Pages может обновляться 1–2 мин).

### Нейминг файлов в `docs/`

По общему правилу: `YYYY-MM-DD — тема — тип.md`. Пример: `2026-08-11 — статус плана развития — отчет.md`.

## Правила

- Это отдельный репозиторий (origin: `basilvs/customstech-landing`). Не выходить за его папку.
- Без разрешения не удалять и не переименовывать файлы, не отправлять данные вовне.
- Стек намеренно vanilla — **не добавлять** фреймворки, сборщики, package.json, npm-зависимости без явного указания пользователя.
- Форма демо — макет. Не делать «настоящую» отправку без указания.
- Язык интерфейса и контента — русский. Мета-теги — русские.
- Результат работы: список изменённых файлов + краткий отчёт, без пересказа того же самого.
